## 1. Requirements

- **.NET 8 SDK**
- **Java 11+** (only needed to build/update the APTreeDSL tool jar — see Step 1)
- **Python 3.10+** with `flask` and `requests` (for the PDDL planning service)
- **ENHSP JAR** (`enhsp.jar`) accessible on the machine running the planning service

## 2. Step-by-Step How-To

### Step 1 — Generate inputs from APTreeDSL

Several files consumed by the execution engine are **generated by the APTreeDSL project** and must be regenerated whenever the domain model changes. Run these from inside the `APTreeDSL/` directory:

**C# type files** (copy into `src/ModelLoader/ParameterTypes/`, `PredicateTypes/`, `ActionTypes/`):

```bash
gradle generateCSharpParameterTypes   # → generated_csharp/ parameter types
gradle generateCSharpPredicates       # → generated_csharp/ predicate types
gradle generateCSharpActionTypes      # → generated_csharp/ action types
```

Copy the output from `APTreeDSL/generated_csharp/` into the corresponding folders under `APTreeExecutionEngine/src/ModelLoader/`.

**Behavior tree JSON model** (the main model file loaded at runtime):

```bash
gradle runAPTreeTool
```

This produces `BehaviorTreeModel.json`. Copy it to `APTreeExecutionEngine/src/ModelLoader/BehaviorTreeModel.json`.

> See the APTreeDSL README for full details on defining models before generating.

---

### Step 2 — Prepare the runtime configuration

Create or edit a `*Config.json` file (see `src/ModelLoader/DemonstratorConfig.json` as a template):

```json
{
  "timeoutSeconds": 30,
  "plannerPath": "/home/ubuntu/ENHSP-Public/enhsp.jar",
  "subtreeConfigName": "ENHSP_Demonstrator",
  "subtreePlannerName": "Enhsp",
  "subtreeDomainFile": "./Plannerinputs/static/Demonstrator/DomainMLTruss.pddl",
  "subtreeEnhspConfig": "sat-hmrph",
  "subtreePlannerPath": "/home/ubuntu/ENHSP-Public/enhsp.jar",
  "subtreeTimeoutSeconds": 30,
  "maxTicks": 3500,
  "tickDelayMs": 10
}
```

See the [Configuration file reference](#configuration-file-reference) section for all available fields.

---

### Step 3 — Start the Python PDDL planning service

The execution engine calls a local Flask service to invoke ENHSP. This service can run locally or on a remote VM accessed via an SSH tunnel.

**If running on a remote VM:**

Open a dedicated terminal and keep it open:

```bash
ssh -L 5000:localhost:5000 -i ~/.ssh/id_ed25519 ubuntu@<vm-ip>
```

**On the VM (or locally), set up once:**

```bash
cd APTreeExecutionEngine/python_service
python3 -m venv pddl_env
source pddl_env/bin/activate
python -m pip install flask requests
```

**Start the service:**

```bash
source pddl_env/bin/activate
python pddl_planning_service.py
```

**Health check:**

```bash
curl http://localhost:5000/health
```

> The ENHSP JAR must be present at the path set in `plannerPath` / `subtreePlannerPath` in your config. Default expected path: `/home/ubuntu/ENHSP-Public/enhsp.jar`.  
> To copy it to the VM: `scp -i ~/.ssh/id_ed25519 /path/to/enhsp.jar ubuntu@<vm-ip>:/home/ubuntu/ENHSP-Public/enhsp.jar`

---

### Step 4 — Build and run the execution engine

```bash
cd APTreeExecutionEngine
dotnet build BehaviorTreeMainProject.csproj
dotnet run --project BehaviorTreeMainProject.csproj
```

By default this starts the frontend API server on port 5254. See [Run Modes](#3-run-modes) for other options.

**URLs (server mode):**

| Endpoint | URL |
|---|---|
| Health | `http://localhost:5254/health` |
| Swagger | `http://localhost:5254/swagger` |
| Decorator catalog | `http://localhost:5254/api/catalog/decorators` |
| Service catalog | `http://localhost:5254/api/catalog/services` |
| Flow catalog | `http://localhost:5254/api/catalog/flows` |

## 3. Run Modes

Pass a mode flag to `dotnet run`:

| Flag | Purpose |
|---|---|
| *(none / `--server`)* | Start the frontend API + WebSocket server (default) |
| `--run <model.json> [config.json]` | Run a BT directly from a JSON model file |
| `--run <model.json> [config.json] --faults <faults.json>` | Run with fault injection enabled |
| `--test` | Run the built-in `DemonstratorTreeTest` |
| `--loadtest` | Run `JsonBTLoadTest` |

Examples:

```bash
# Default server
dotnet run --project BehaviorTreeMainProject.csproj

# Run a model directly
dotnet run --project BehaviorTreeMainProject.csproj -- --run src/ModelLoader/BehaviorTreeModel.json src/ModelLoader/DemonstratorConfig.json

# Run with fault injection
dotnet run --project BehaviorTreeMainProject.csproj -- --run src/ModelLoader/BehaviorTreeModel.json src/ModelLoader/DemonstratorConfig.json --faults DemonstratorFaults.json
```

## 4. Reference

### Project structure

```
src/
  Program.cs                  # Entry point — mode dispatch
  FrontendServer.cs           # ASP.NET Core API + WebSocket server
  ModelLoader/
    BehaviorTreeModel.json    # ← Generated by APTreeDSL (gradle runAPTreeTool)
    BehaviorTreeRunner.cs     # Loads the JSON model and builds the BT.
                              #   Root node is a DynamicFlowNode. Its children
                              #   are also DynamicFlowNode nodes, each wrapped in
                              #   a DynamicFlowNodeWrapper (PActionNode) and
                              #   connected in the root's NodeGraph with MEETS
                              #   (sequential) temporal relations.
    BehaviorTreeConfiguration.cs  # Runtime config (loaded from *Config.json)
    DemonstratorConfig.json   # Example runtime configuration
    ParameterTypes/           # ← Generated by APTreeDSL (gradle generateCSharpParameterTypes)
    PredicateTypes/           # ← Generated by APTreeDSL (gradle generateCSharpPredicates)
    ActionTypes/              # ← Generated by APTreeDSL (gradle generateCSharpActionTypes)
  Actions/                    # ActionNode base classes (HL, LL, parametric)
  FlowNodes/                  # DynamicFlowNode + DynamicFlowNodeWrapper execution logic
  Services/
    AIPlanning/               # PDDL planning service integration (calls Flask)
    FaultInjection/           # Fault injection runtime
  Blackboard/                 # Shared blackboard state
  Graph/                      # NodeGraph / causal link execution
  Tree/                       # BT tick loop
  Logs/                       # Logging infrastructure
python_service/
  pddl_planning_service.py    # Flask wrapper around ENHSP
  enhsp.jar                   # ENHSP planner JAR (not committed — provide separately)
  Plannerinputs/              # PDDL domain and problem files
docs/
  architecture-class-diagram.puml
  planutils-planner-overview.md
```

### Configuration file reference

| Field | Type | Description |
|---|---|---|
| `timeoutSeconds` | int | Planner timeout for high-level planning calls |
| `executionActive` | bool | **Robot execution toggle.** `true` (default): `ServiceLLSubtreeInject` expands ML actions into LL subtrees and sends robot commands. `false`: LL injection is skipped — only HL→ML PDDL planning runs (planning-only mode). |
| `executionMode` | string | How the planner arranges generated HL plan actions in the NodeGraph: `Sequential` (MEETS constraints — one after another), `Parallel` (OVERLAPS — all at once), or `Hybrid` (mix of both). This is a planner arrangement setting, not a robot execution toggle — see `executionActive` above. |
| `plannerPath` | string | Absolute path to `enhsp.jar` on the planning machine |
| `subtreeConfigName` | string | Name tag for the ML subtree planner config |
| `subtreePlannerName` | string | Planner type for ML subtrees (e.g. `Enhsp`) |
| `subtreeDomainFile` | string | Path to the PDDL domain file for ML subtrees |
| `subtreeProblemFile` | string | Path to the PDDL problem file for ML subtrees |
| `subtreeEnhspConfig` | string | ENHSP search config (e.g. `sat-hmrph`) |
| `subtreePlannerPath` | string | Path to `enhsp.jar` for ML subtree planning |
| `subtreeTimeoutSeconds` | int | Timeout for ML subtree planning calls |
| `subtreeExecutionMode` | string | Same as `executionMode` but for ML-level subtree planner arrangement |
| `maxTicks` | int | Maximum number of BT ticks before stopping |
| `tickDelayMs` | int | Delay between ticks in milliseconds |
